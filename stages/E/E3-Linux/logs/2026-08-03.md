### 6. SSH 端口转发

在 Ubuntu 中启动：

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

在 Windows 建立本地端口转发：

```powershell
ssh -N -L 9000:localhost:8000 ysyx-vm
```

然后通过浏览器访问 `http://localhost:9000`，成功打开 Ubuntu 中的网页。

理解了：

```text
-L    本地端口转发
-N    只建立隧道，不打开远程 Shell
-f    认证后转入后台
```

还使用 `Get-NetTCPConnection` 和 `Stop-Process` 找到并关闭了后台 SSH 隧道。

### 7. 正式练习

完成了：

- `pgrep` 根据名称查找进程
- `pkill` 根据名称结束进程
- `wait` 等待后台子进程
- 使用 `kill -0` 检查进程是否存在
- 编写 `pidwait.sh`

`pidwait.sh` 的核心逻辑：

```bash
while kill -0 "$pid" 2>/dev/null; do
    sleep 1
done
```

今天重点理解了：

```text
kill -0 PID        只检查进程，不终止进程
2>/dev/null        丢弃标准错误提示
退出状态           决定 while 是否继续
```

## 今日遇到的问题

1. 后台 SSH 隧道使用 `-f` 后，`Ctrl+C` 无法关闭。
   - 原因：SSH 已经转到后台。
   - 解决：通过监听端口找到 PID，再使用 `Stop-Process` 结束。

2. 一开始误以为 Ubuntu 中的 `scp ... localhost ...` 会传到 Windows。
   - 实际上“本地”指执行 `scp` 命令的机器。
   - 在 Windows PowerShell 执行 `scp`，本地才是 Windows。

3. 对 `2>/dev/null` 一直不理解。
   - 今天明确了：`2>` 重定向标准错误，`/dev/null` 会丢弃内容。
   - 它只隐藏错误文字，不改变命令退出状态。
