## 一、Ex15 基础内容复习

通过 `ages` 和 `names` 两个数组，进一步理解了数组与指针之间的关系。

```c
int ages[] = {23, 43, 12, 89, 2};

char *names[] = {
    "Alan", "Frank",
    "Mary", "John", "Lisa"
};
```

掌握了以下几种等价访问方式：

```c
ages[i]
*(ages + i)

names[i]
*(names + i)
```

核心关系：

```c
a[i] == *(a + i)
```

数组下标访问本质上可以理解为“基地址 + 偏移 + 解引用”。

## 二、故意制造错误并观察结果

### 1. 错误的指针类型

尝试将 `names` 错误地作为 `int *` 使用：

```c
int *cur_age = (int *)names;
```

虽然强制类型转换可以让编译器不再直接阻止，但程序会把原本保存的字符串指针地址按照 `int` 来解释，从而打印出错误的年龄数据。

理解：

- 强制类型转换不能保证程序逻辑正确；
- 指针类型决定了解引用时如何解释内存；
- 当前 64 位环境下 `char *` 通常为 8 字节，而 `int` 为 4 字节，因此错误解释内存会产生明显异常结果。

### 2. 数组越界

把原本的循环边界：

```c
(cur_age - ages) < count
```

故意改成：

```c
(cur_age - ages) <= count
```

运行后观察到：

```text
offset = 5
Segmentation fault (core dumped)
```

理解：

- 长度为 5 的数组合法下标只有 `0~4`；
- `ages + 5` 可以作为“尾后指针”参与比较，但不能解引用；
- 一旦访问 `ages[5]` 或 `names[5]`，就发生越界访问，属于未定义行为；
- 本次实验中最终触发了段错误。

## 三、倒序遍历数组

实现了从最后一个元素向第一个元素倒序访问。

最终采用更安全的写法：

```c
cur_age = ages + count;
cur_name = names + count;

while (cur_age != ages) {
    cur_age--;
    cur_name--;

    printf("%s lived %d years so far.\n",
           *cur_name, *cur_age);
}
```

得到倒序：

```text
Lisa
John
Mary
Frank
Alan
```

理解了一个重要规则：

> 正向遍历可以走到尾后位置再停止；倒序遍历可以从尾后位置开始，先自减再访问。

## 四、完成官方附加题中的数组/指针改写

### 数组访问改为指针访问

把：

```c
names[i]
ages[i]
```

改为：

```c
*(names + i)
*(ages + i)
```

程序输出保持一致。

### 指针访问改为数组访问

对于：

```c
char **cur_name = names;
int *cur_age = ages;
```

使用：

```c
cur_name[i]
cur_age[i]
```

同样可以正确访问元素。

进一步理解：

> 数组和指针不是完全相同的东西，但在很多表达式和函数参数中可以使用相似的访问语法。

## 五、使用指针处理命令行参数

创建 `ex15_args.c`：

```c
char **cur_arg = argv;

while (*cur_arg != NULL) {
    printf("%s\n", *cur_arg);
    cur_arg++;
}
```

运行：

```bash
./ex15_args hello ysyx linux
```

输出：

```text
argc = 4
./ex15_args
hello
ysyx
linux
```

理解：

```c
argv
```

本质上可以作为一个 `char **` 来遍历。

其中：

```c
*cur_arg
```

得到当前的字符串指针，

```c
cur_arg++
```

移动到下一个命令行参数。

## 六、理解 `*&` 和 `&*`

创建 `ex15_address.c`。

实验结果：

```text
age = 23
*(&age) = 23
*p = 23
&(*p) == p : 1
```

理解：

```c
*(&age)
```

表示先取得 `age` 的地址，再解引用，最终仍然得到 `age` 的值。

```c
&(*p)
```

表示先解引用指针找到对象，再取得该对象地址，在 `p` 是合法有效指针的情况下结果与 `p` 相同。

可简化记忆为：

```text
*&x -> x
&*p -> p
```

## 七、使用 `%p` 观察真实地址

在 Ex15 中打印 `ages`、`cur_age`、`names`、`cur_name` 的地址。

观察到：

```text
ages + 0 -> ...f70
ages + 1 -> ...f74
ages + 2 -> ...f78
```

相邻地址相差 4 字节，因为：

```c
sizeof(int) == 4
```

同时：

```text
names + 0 -> ...f90
names + 1 -> ...f98
names + 2 -> ...fa0
```

相邻地址相差 8 字节，因为当前 64 位环境中：

```c
sizeof(char *) == 8
```

进一步理解：

```c
p + 1
```

不是简单地让地址数值增加 1，而是移动：

```text
sizeof(*p)
```

个字节。

## 今日收获

今天最大的收获不是记住某一种写法，而是建立了对指针的统一认识：

```text
数组元素访问
    ↓
基地址 + 偏移
    ↓
得到目标元素地址
    ↓
解引用得到值
```

同时进一步理解了：

- 指针类型的重要性；
- 指针算术按照元素大小移动；
- 数组越界会产生未定义行为；
- 尾后指针可以存在但不能解引用；
- `argv` 本质上也可以按照指针数组理解；
- 数组和指针语法存在联系，但二者不能简单认为完全相同。
